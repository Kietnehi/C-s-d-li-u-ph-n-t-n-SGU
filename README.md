## 4. General Project Summary – SQL Server (FundManagement)

### 🎯 Goal

Build a **FundManagement** system to serve investment fund management,

then **distribute data** across multiple SQL Server sites to:

* Reduce load on individual nodes.
* Provide data redundancy in case of failure.
* Allow parallel processing.

### ⚙️ Fragmentation and Replication

* **Fragment the `Clients` table** by `RiskProfile` (`Low`, `Medium`, `High`).
* **Fragment the `Funds` table** by `FundType` (`Equity`, `Bond`, `Mixed`).
* **Merge Publication Replication** for 2-way synchronization.
* **Linked Server** used to consolidate global queries.

---

## 5. Specialized Project – Hadoop & MapReduce 🧠

> **Topic by Truong Phu Kiet – achieved a score of 9.5/10 (Highest in Class).**

### 🔍 Goal

Understand the mechanism of distributed storage and processing on the **Hadoop Ecosystem**,

including **HDFS**, **YARN**, and **MapReduce**,

comparing performance between **local, Docker, and AWS** environments.

### ⚡ Key Experiments

* Write a **WordCount** program.
* Deploy in 4 environments:
1. Sequential Python
2. Hadoop Single Node
3. Hadoop Docker 3 Nodes
4. Hadoop AWS Cluster


* Result: **More nodes → faster processing speed**.

### 📦 Basic HDFS Commands

```bash
hdfs dfs -mkdir /input
hdfs dfs -put data.txt /input
hadoop jar hadoop-mapreduce-examples-3.3.0.jar wordcount /input /output
hdfs dfs -cat /output/part-r-00000

```

## 6. Connection Between Both Parts

| ⚙️ **Comparison** | 🧩 **SQL Server (Replication)** | ☁️ **Hadoop (MapReduce)** |
| --- | --- | --- |
| 🎯 **Goal** | Distribute operational data | Distribute big data processing |
| 🧠 **Mechanism** | Publisher → Distributor → Subscriber | HDFS → YARN → MapReduce |
| 🗂️ **Data Type** | Structured, transactional | Unstructured, logs, large text |
| ⏱️ **Sync** | Near real-time / Continuous Replication | Batch Processing by Job |
| 💻 **Language / Tool** | SQL / T-SQL, Linked Server, Replication Agent | Java / Python, HDFS CLI, Yarn ResourceManager |
| 💼 **Real-world App** | Fund management, Banking, ERP systems | Log analysis, Big Data, Machine Learning, ETL |

> 🧩 Both models **belong to the distributed field**, but have different objectives:
> * **SQL Server** → aims for **consistency and operational data synchronization**.
> * **Hadoop** → optimizes for **parallel big data processing and fault tolerance**.
